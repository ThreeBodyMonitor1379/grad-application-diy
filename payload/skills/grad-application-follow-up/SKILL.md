# 收到提醒以后：先认清学校还在等什么

从原通知定位项目、入学季、事项、发送时间、校方要求和入口。可能是群发的条件提醒、针对一个附件的要求、针对一位老师的一封推荐提醒，或者只是已收申请的回执。**申请已交不等于材料齐全；上一封提醒也不是今天的门户状态。**

## 按事项核查

- 推荐：每个“项目 × 推荐人”各一条；查看申请人端的推荐状态和最后成功回读时间。区分邀请已发、老师已获邀请、报告已交、学校已收；只有前两项时不称完成。老师在项目甲已交不能替代项目乙。若官网只公布项目申请截止，不据此推算推荐截止；邀请中的建议日期与上锁期限分开。老师的保密报告由老师本人处理，不索取账号、密码、唯一链接、评分或签名。
- 附件：将要求拆成签发学校、语种、学期覆盖、版本、递交渠道。双学籍时校甲的中英文成绩并不是校甲和校乙两套成绩，检查实际缺的是哪一所的哪一版。原信若写“已上传则无需动作”，先查申请人门户已有附件；能预览时对照实际页，不能预览就注明只核到了文件名与本地版本。若相符且无新缺件提示，不重复上传；证据冲突时列出缺口，向指定单位问清，不擅自删除旧件或改用邮件投递。
- 延期或更正：查原线程，区分草稿、已发、书面批准、门户更新、最终收到。记录获准范围：哪个项目、哪位推荐人或哪份文件、新期限及原文有无时区。另一项目不能沿用。日期冲突且临近时标红较早日期用于保守安排，同时向校方询证，不能自称已延期。
- 登录过期、某一页空白或附件不能预览：保留上次成功核验的时间；不把缺证写成未交。若多个项目在不同时刻回读，逐行列时点，不把汇总称同时实时。

## 给申请人的结果

每条写“项目／事项 → 当前状态和依据 → 硬期限或未公布 → 谁做什么 → 何时停止”。先列确需动作的项，再一行说明哪些已齐。已收到或已批准的事项不再催。只有明确授权才对外发信、上传或重发邀请；发送之前核对象、查重，发送后以实际发件记录为据。没有回应时不要自动重试。

虚构例：学院昨天发来模板提醒；今天项目甲的推荐页显示甲老师的报告已收到，项目乙仍只显示邀请已发。结果应为“甲停止催办；乙先核该项目邀请和截止，有需要由老师本人提交”。若乙页面不可访问，就写“上次仅见邀请；今天无法复核”，不要求两位老师都再交一次。

未提交申请的材料如何填写属于材料核对；拿到明确录取信后的接受与付款期限属于 Offer 核对。
